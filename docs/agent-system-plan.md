# Agent system plan

`docs/architecture.md` (the architecture) is the source of truth. This file records where the code departs from it and what is built so far.

## Decisions that depart from the architecture

| Decision | Chosen | Why |
|---|---|---|
| Core language | Rust for the agent loop, providers, storage and tools. The UI is web tech in the Tauri webview. | Owner override of arch §6.2. Provider calls and streaming live next to the Tauri shell with no second IPC layer. Prompts stay as Markdown, editable without a rebuild. |
| Frontend build | Plain ES modules with vendored `marked`, `DOMPurify`, `KaTeX`, Prism (core plus a fixed language set) and Mermaid (lazy). No bundler. | R1 (lightweight). Nothing in the UI needs a compile step yet. |
| Dev server | None. The old `crates/container` HTTP server was removed. | R1 forbids a separate server process. Its logic duplicated the Tauri commands. |
| Keyless web search | Wikipedia search API. | DuckDuckGo's HTML endpoint serves its bot page to Rust HTTP clients. Mojeek serves a captcha. |

## Decisions for the agent runtime

These settle what the architecture left open. Recorded before code so the choices are auditable.

| Decision | Chosen | Why |
|---|---|---|
| Prompt bundling | `build.rs` walks `prompts/**` and generates a `path -> &'static str` map (via `include_str!`). | `include_dir` is not in the offline crate cache; a build script is dependency-free and gives a compile-time map. |
| Plugin manifests | `plugin.toml` parsed by the `toml` crate into serde structs with `deny_unknown_fields`, validated by `plugins::manifest::validate`. The old frontmatter parser is deleted. The seven briefs that stay plugins were migrated to the package layout as unloadable catalogue entries in `plugins/catalog/<id>/` (manifest, `prompts/tutor.md`, input schemas; tools renamed to the `<id>_` rule; native ones marked by their permissions); the `demo`/`figure` briefs' tutor-side rules moved into `jobs/demo-builder.md` and `jobs/figure-maker.md`. Listed in `docs/plugins.md` §11 and `prompts/README.md`. | A typo in an AI-written manifest must fail loudly, not silently drop a permission or an agent scope. One manifest convention (build prompt W5, clean cutover) without losing the briefs' contracts. Nothing loads the catalogue, so it cannot reach a prompt or a test. |
| HTML→text for `page_fetch` | Small in-tree stripper (drop script/style, tags → text, collapse whitespace). | `html2text` is not in the offline crate cache. |
| Streaming text display | `Message` content is `Vec<ContentBlock>`; the harness builds replay blocks, and the UI streams only `Text` deltas. | Content blocks are required by M1; the runtime owns the single copy of text. |
| Cross-wire `Native` blocks | Dropped in `body()` when `block.wire != endpoint.wire`. | Spec: replay unchanged only to the same wire. |
| `session_state` `learner_state` | Renders `no graph yet` (no graph built, out of scope). | Out-of-scope seam, §4. |
| Per-session locking | One `tokio::sync::Mutex` per session (map behind a `std::sync::Mutex` that is only held to look it up). A tutor turn, a learner `answer`/`approve`, and a job delivery each hold it; planner and researcher jobs never do (they only append ops). No std lock is held across an `.await`. | M7.8; also the mechanism of the delivery rule (a result can't interleave into a running turn). |
| Job delivery | A job's result is persisted on its `job` op (`done`/`failed`). Delivery takes the session lock, skips if an answer is pending (the next tutor turn delivers first), else appends a tagged user message (`research-brief` / `plan-notice`, with `jobId`) and wakes the tutor in Measure/Teach/Close. A message's `jobId` marks the result delivered, so pending deliveries are derivable after a restart. | M4 delivery rule; resumable. |
| Scope `brief` op | Written when the scope brief is *delivered*, not when the researcher submits it. | The `probe_done` gate then means "the tutor has the brief in its conversation", never just "it exists in the log". |
| Tool op shape | Two ops per call, matched by `callId`: the call (before acting, no `result`) and the result (`args` omitted). Planner tool ops carry `agent: "planner"` and are not part of the tutor's messages. Researcher tool loops stay in memory. | An append-only log can't fill in a result; the planner's loop is not conversation; jobs don't touch the conversation (prompts/README). |
| `questionId` | The `question_ask` call id. The learner's answer result includes it as `questionId`, so `verdict_record` and `probe_done.evidence` can cite it. | The contract had no id field; the tool contract in `crates/harness/prompts/README.md` documents it. |
| Op ordering | Op ids come from a process-wide monotonic ULID generator, so two ops written in one millisecond replay in write order (`at`, then `opId`). | A tool call and its result are often written in the same ms. |
| Plan phase | `Plan` is used for the initial planning only. Revisions (learner or `plan_change_request`) run the planner as a background job while the session stays in Teach; only a revision that needs approval moves to `awaitApproval`. | The tutor and learner keep talking while the planner thinks; matches "Plan → Teach: plan_keep, or a minor change". |
| Teaching position | The current section is always "the first plan section not closed by an accepted `section_done`", recomputed on approve and on applied revisions. | A section added before the current one (missing foundation) is taught next. |
| Plan plugins | On approval (and on applied revisions) each open section's plugins that the learner didn't remove become `pluginGrant` ops with `by: "plan"`. Active plugins = grants for the current section still listed by the plan, plus `by: "request"` grants. | One source of truth for active plugins. |
| Hand-off line | After `probe_done` the tutor gets one more model call with its Measure prompt and tools (any call is answered "not run") so it can tell the learner the plan is being built. | `measure.md` asks for that line; Anthropic rejects tool history without tools. |
| Compaction | Tutor only; the planner reads the same compacted conversation. The compaction turn uses `compaction.md` as the system prompt with no tools; the cut is always just before a learner-side message with no call awaiting its result, keeping ≥ 20% of the window verbatim. Context window from the provider catalog, else 100k. | Simplest form of arch §4.15 that never splits a call from its result. |
| Events | One process-wide event sink (`set_event_sink`); Tauri forwards it through a coalescer (16 ms / 2 KB) to a channel the UI registers with `subscribe_events`. Practice keeps the per-call channel. | Jobs and wakes emit after the command that caused them returned. |
| Title index | Titles from `title` ops are cached in `<config>/session-index.json` (device-local, write-then-rename, rebuilt by one full scan when missing). | `list` reads only two lines per file. |
| Job recovery | Opening a Learn session marks jobs left `queued`/`running` by a previous run `aborted` and starts them again from their persisted `args`; undelivered results are delivered. | Otherwise a lost scope job blocks `probe_done` forever. |
| Redaction | Error text persisted in `job` ops or shown via `turnEnd` has every saved/env credential string replaced with `[redacted]`. | No secrets in op logs. |
| `tracing` | Added as a dependency (cached); `debug` events for model calls (first token, total), tool time, turn time and job duration. No subscriber is installed by the library. | M7.9. |
| Capability values | `capabilities` fields are `Option<bool>`; catalogs leave `None` = unverified. | M1/M2 warnings show "unverified". |
| Legacy sessions | Learn sessions without a `phase` op are read-only; Learn sessions are created with a `phase` op on line 2, Practice sessions without one (Practice is never read-only). `learn.md` and its loader branch are deleted. | M4 clean cutover. |
| Map before the graph builder | The Map page draws a real knowledge graph from `<repo>/graph/` through one read-only `knowledge_map` command (topics, propositions with descriptions and kinds, prerequisite edges, per-topic check totals); `cargo run -p harness --bin import_learnharness` writes that directory from the learner's own LearnHarness data, and `cargo run -p harness --bin port_learnharness_session` ports one chat into a session op log whose plan is built from those propositions (ui-design §7.6). | Graph storage existed as plain files before any extractor did; building the Map on it forced the data model (single-home topic tree, cross-topic prerequisites) into the open instead of letting session plans masquerade as knowledge. The importer's topic tree and home-topic classification are **[inference]**, marked as such in its module doc; the extractor from live sessions (arch §4.7) is still missing (Not built yet 1). |
| Edges from a model pass, validated by code | `cargo run -p harness --bin extract_edges -- <repo> [--dry-run] [--limit n] [--accept]` asks the configured Planner role for `requires`/`contrasts` edges, one call per topic plus one cross-topic call, and writes them to `graph/edges.proposed.jsonl` with a `why` per edge. Only code decides what survives: unknown ids, self-edges, duplicates of `edges.jsonl`, anything that would close a cycle, an empty `why`, an unknown relation — reported, never written. `--accept` merges the reviewed file into `edges.jsonl`. | The owner's ruling (2026-11-07) after seeing which claims had no recorded prerequisite: wording-based heuristics make wrong edges, and the UI would then teach against them. A proposal file keeps the model's judgement auditable — every edge carries the sentence that justifies it — and keeps acceptance a deliberate act while the reviewed graph is still plain files. The pass also surfaced a real defect: the source's chains contained a 2-cycle, which the importer now breaks deterministically. |

## Decisions in the output, plugin and material build (2026-11-06)

One row per non-obvious choice the code makes; the reasons are the ones the code and `docs/plugins.md`/`docs/architecture.md` §4.20–4.25 give.

| Decision | Chosen | Why |
|---|---|---|
| Plugin runtime | Luau via `mlua` (`luau` feature), one VM per plugin, built lazily and reused; `StdLib::ALL_SAFE` minus `io`/`os`/`debug`/`package`/`dofile`/`loadfile`/`loadstring`/`load`/`collectgarbage`, then `sandbox(true)`. | D6; the sandbox plus memory cap and interrupt are the smallest runtime that runs on every target. |
| Plugin limits | 64 MiB per VM; 2 000 ms per tool call; 200 ms per view call; 16 KiB tool text; 3 tools per plugin; 250 words per fragment; one renderer and one view. | Bounded worst case for AI-written code; a limit hit is a tool error and the VM is discarded. |
| Entry module loading | `src/main.luau` is evaluated once per VM and its exports table cached; `require` caches modules per name for the VM's life. A VM error or a folder plugin's file change starts a new VM, which re-reads it. | No re-read/recompile inside the 200 ms view budget, and an installed `<sha256>` package runs what was loaded, not whatever is on disk later; folder plugins still pick up edits through the fingerprint reload. |
| VM recreation | Any error in a call (limit hit, Lua error, missing export) drops the VM; the next call builds a new one. Build prompt W5 only required this for limit hits. | A VM left mid-call after an error may hold half-updated module state; a fresh VM is the one state known to be clean. |
| Host API | Pure functions only: `json`, `svg`, `num` (real/complex, LU solve), `rand` (seeded), `log` (tracing). | No I/O means no permission model in api 1; a seeded PRNG keeps figures reproducible. |
| Tool result shape | Non-artifact: string, `{text}`, or JSON of the table. Artifact: `{ text?, artifact = { kind = "svg", svg, data? } }` as in build-prompt W6. | One decoding path for every plugin, and the shape W6 names; errors are returned as `plugin error: …` instead of crashing the turn. |
| Manifest strictness | `deny_unknown_fields` everywhere; `api` must equal 1; `permissions` must be empty for Luau; tool names must start with `<id>_`; an id whose `<id>_` prefix begins any core tool name (from `tools::tutor_tools`/`planner_tools`/`researcher_tools`) is refused; agents restricted to `tutor`/`practice`. | A typo must fail at load/install time, not silently weaken scoping. A colliding prefix would duplicate or shadow core tools. Reserved agent names are rejected until those agents exist. |
| Artifact payload | Tool returns `artifact.data` + fallback `artifact.svg`; core stores an `artifact` op with a ULID and a sanitised fallback; the model gets a handle and one placement line. | W6/D7: the model places the figure after seeing the tool's feedback; replay needs no plugin. |
| SVG sanitising | Core strip of `script`, `foreignObject`, `iframe`, `object`, `embed`, `audio`, `video`, `animate`, `set`, `style`; `on*` attributes; external refs and `javascript:`; 256 KiB cap; UI re-sanitises with DOMPurify's SVG profile. | Plugins are untrusted; the stored fallback must be safe in replay and on every platform. |
| Renderer | `[[renderer]]` is required when a tool sets `artifact = true`, and `LuauPlugin::render(data)` is implemented. The `artifact.svg` the tool returned is the stored fallback; the `circuit` view also calls `render` (in `[[view]].calls`) after a slider move, so the schematic matches the new solved values. | W6: storing the tool's own drawing keeps replay exact; the view needs a fresh drawing because the stored one would otherwise show a stale probe value. |
| View isolation | `<iframe sandbox="allow-scripts">` with no `allow-same-origin`, loaded from the shell's `pluginview` URI scheme (`pluginview://localhost/<id>`; `http://pluginview.localhost/<id>` on Windows/Android) whose response carries the view CSP header (`sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; …; connect-src 'none'`); source-checked `postMessage`; allow-list from `[[view]].calls`; package CSS/JS inlined. Build prompt W7 said `srcdoc`. | A `srcdoc` frame inherits the app CSP (`script-src 'self'`), which blocks the view's inline script: measured in headless Chromium 155 (blocked under the app CSP, runs without it, runs from a separate origin with the view CSP). Its own document keeps the app CSP strict. D8 and GHSA-57fm-592m-34r7: an IPC-escape probe view failed every attempt (`docs/plugins.md` §7.2). |
| View protocol | `init` (artifact data, theme tokens, answer flag), `theme` (tokens after a light/dark switch), `call`/`result`, `resize` (clamped to 160 px … 80 % of the window height), `state` (≤ 500 chars, ≤ 1 per 250 ms), `submit`; every message carries `protocol: 1`. After a submit the frame is inert (`aria-disabled`, only `resize` still handled). The `theme` message is beyond W7. | Versioned and small; `state` is the only interaction that reaches the tutor, so slider moves do not flood the conversation. Without `theme` a view stays light in a page switched to dark. An inert frame cannot change a submitted answer or log state for it. |
| Answer mode | `question_ask.view { artifactId, task, target }`; the core checks the artifact exists and the plugin's view declares `answer`; `grade` returns `{correct, detail}`; the plugin never records a verdict. | W7: grading policy stays in the agent loop (`verdict_record`), the component only judges its own figure. |
| Registry index | One `index.json`, `registry: 1`, snake_case two-word keys (`use_when`, `avoid_when`, as in build-prompt W8 and `plugin.toml`), `versions[]` with `url` + `sha256`; HTTPS, `file://` or an absolute path. `plugin_search` output to the model uses `useWhen`/`avoidWhen`. | D9; the index mirrors the manifest's own key names. |
| Plugin storage locations | Installed packages at `<app config dir>/plugins/<id>/<sha256>/`, index cache at `<app config dir>/registry-cache/<sha256(url)>.json` (build prompt W8 said app data dir and app cache dir). | One device-local root next to `settings.json`, the file that lists the registries and folders; the cache is small. |
| Install | Verify sha256 (archive ≤ 16 MiB), unpack `.tar.gz` (root or one top-level dir; ≤ 16 MiB per entry, 64 MiB total), refuse `..`/absolute entries and ids that aren't valid plugin ids, copy to `<config>/plugins/<id>/<sha256>/`, validate the manifest and that id/version match, then register (a disabled id stays disabled). | Content-addressed installs make rollback and duplicate versions harmless; a corrupt archive fails before anything is recorded; ids and hashes are path segments, so they must be safe. |
| Lock | `plugins.lock` in the data repo, sorted by id, `{id, version, sha256, source: {registry}|{folder}}`; `sha256` is the index digest for installs and the package content hash for folders; written on install, folder add and remove; `missing_locked` lists registry entries whose locked `<id>/<sha256>` copy is absent and folder entries not loaded; an unparseable lock is an error, never rewritten as empty. | Sync carries the learner's choices; folder sources cannot be fetched elsewhere, so those devices fall back; a corrupt lock must not lose entries. |
| Registry settings | `settings.json` `registries` (the learner's own), `hideDefaultRegistry`, `pluginFolders`, `disabledPlugins`. The owner's registry is built in as the default (`install::DEFAULT_REGISTRY_URL`), listed unless hidden, and fetched at startup when its cache is missing or over a day old. | The owner published one; storing it in settings would never reach devices whose `settings.json` already holds `registries: []`, and a cache-only browser needs the fetch to show anything. Additions and enable/disable stay device-local choices. |
| Folder plugins | Added by canonical path; stored in settings and the lock; loaded at startup and on add; a folder copy wins over an installed copy with the same id. No background file watcher: a fingerprint of the package files (mtime + size, excluding `tests/`) reloads the manifest, schemas, fragments and VM on next use when any file changed; a failed reload keeps the last good package and exposes `loadError` in `plugins()`. | W8 asked for reload on change; watching a directory is not available on every target, and a fingerprint is enough for an edit loop. A broken edit must not make the plugin disappear. |
| Planner catalog | Installed + enabled + available on the platform, one line per plugin; plan validation also accepts an uninstalled id present in a cached registry index *that lists this device's platform*. Code sets each section's `needsInstall: [<id>, …]` at `plan_write` from the installed/enabled/on-platform catalog then, replacing any model value; `plugins` stays a plain id list. The plan card uses `needsInstall` to offer an install chip only for proposed ids (a stale missing id shows plain text), and re-renders from the live installed list so installing updates the card without changing the plan version. | W9/D10: the planner may propose what the learner can install; the code, not the model, knows what is missing. |
| Grants | On approval (and applied revisions), open sections' plugins become `pluginGrant` ops `by: "plan"`; plugins not grantable then (missing, disabled, wrong platform) are left out with one `plan-notice` message (build prompt W9 said "at the start of teaching a section"); after installing, `plugin_request` grants them, capped by the section limit. | One source of truth for active plugins; no silent installs. |
| `plugin_search` | Splits the query into whitespace-separated terms and requires every term to appear (case-insensitive) in id, title, description or `use_when`; only entries listing this device's platform are offered. Returns ≤ 5 uninstalled matches as JSON with permissions, platforms, highest semver version and registry URL. Never fetches. | Multi-word queries like "draw circuits" must still find a plugin; proposing a plugin that can't run on this device wastes a plan slot. Read-only and cheap; never installs. |
| Image staging | Paste, or a picked/dropped/mentioned file → sniff PNG/JPEG/GIF/WebP (≤ 5 MiB) → device-local `<config>/staged-images/`; Send moves it to `attachments/<yyyy>/<ulid>.<ext>` in the data repo; removing the chip deletes it (`unstage_image`); staging is emptied at startup. The op stores the path, media type and size, not bytes. | Sent images must sync and survive a restart, but a removed chip must never be stored or synced; magic bytes beat a browser-provided MIME type or a file name. |
| File/folder references | Not copied; the op stores the path (workspace files relative to the workspace); the model gets one line (`[attached file] <path>, <n> KiB — read it with file_read or file_find`; the hint only for agents with file tools; `<n> B` under 1 KiB; no size for folders); every file or folder attachment outside home becomes a `fileGrant` read root for that exact path. Practice takes images only. Messages always have text (no attachments-only messages). | The learner keeps editing their own material; grants are explicit and survive restarts. Absolute paths in the synced log are the price of a meaningful grant, but never the workspace's. |
| Vision check | If the Tutor role's catalog says `vision: Some(false)`, images are refused before writing; `None` is unverified and does not block. Each request decides by its own role: the planner's context keeps images unless the **Planner** role says `Some(false)`. | W2/W3; never send bytes the model cannot read, but never block a capable model with an incomplete catalog. |
| Workspace storage | `sessionId → canonical path` in `<config>/workspaces.json`; the op log stores only `{attached, name}` (the folder's name, never its path). | D12: the path is device-specific; the name is enough for another device to ask. |
| Workspace write | `workspace_write` (tutor, Teach, workspace attached): resolve inside the folder, create parents, never delete, text extensions only, ≤ 256 KiB, refuse to overwrite unless the current sha256 matches the last read/write hash; op stores path/hash/size. Build prompt W4 also named Practice, which has no tool loop yet. | W4: never clobber a learner's external edit, never destroy work, keep the log small. |
| Workspace prompt | `shared/workspace.md` composed only with the `workspace` flag; one line in `practice.md` and `tutor/phases/teach.md` inside `{{#workspace}}`. | The fragment costs tokens; it should exist only when the folder does. |
| Highlighting | Prism 1.30.0 core + 20 grammar files (`ui/vendor/prism/`, checksums match jsDelivr), loaded as `<script>` elements: core at idle after startup, each grammar on first use; Prism runs in manual mode; blocks are highlighted in an idle callback once final (completed streaming block or finished message), never per delta; unknown language stays plain. | D3. Manual mode stops Prism's load-time `highlightAll` from touching a block that is still streaming. Idle scheduling keeps highlighting out of stream frames (F2 in `docs/ui-design.md`). |
| Mermaid loading | Mermaid 11.12.1 IIFE build (`ui/vendor/mermaid/mermaid.min.js`, 2 749 172 B, checksum matches jsDelivr) added as a `<script>` element on the first `mermaid` block, not `import()`ed as D4 said; `securityLevel: "strict"`, `htmlLabels: false`; a failed render removes Mermaid's scratch node and shows source + one error line. | The IIFE bundle sets `globalThis.mermaid` only as a classic script; imported as a module it threw ("Cannot read properties of undefined (reading 'mermaid')"). HTML labels live in `<foreignObject>`, which the SVG sanitizer drops, leaving empty boxes. |
| Mermaid prompt flag | `mermaid` is always set by the tutor composition. | The UI ships the renderer in the same build; the flag gated the prompt until it did. |
| Artifact placement in the UI | `![alt](artifact:<id>)` resolves to a view (installed plugin, supported platform) or the fallback SVG; unknown id → alt in brackets; unreferenced artifacts appended after the turn in creation order. | W6: the figure sits beside the sentence, and nothing is lost when the model forgets the reference. |
| Circuit view | `[[view]].calls = ["solve", "render"]`: after a slider move the view solves, then redraws the schematic through the plugin's own renderer; slider values carry units (`aria-valuetext`, e.g. "1.5 kΩ"); `state` is posted only after the learner moved something ("R2 = 1.5 kΩ, Vout = 4 V"), never on load. Sources are drawn with leads and +/− on the `to`/`from` side; labels sit beside vertical parts and above horizontal ones. | W10: without the redraw the schematic kept the stored "Vout: 3 V" while the table said 4 V. A state line on load would add a `viewState` op for every figure each time a session opens. |
| Composer send | Attachments leave the composer only on Send (`takeForSend`); with a `vision: Some(false)` role, image chips read "This model can't see images" and Send asks once ("Send without images" / "Keep editing"); a rejected send puts text and chips back. | W3; the learner decides about the images before anything is written. |
| Grade argument shape | The host calls `grade(answer, target)` with the view's `submit { answer }` value exactly as the view sent it (no wrapper), and returns `{ questionId, artifactId, answer, view }` to the tutor. | The plugin that drew the view defines its own answer shape; the core only carries it. |
| View state storage | The core holds the latest sanitized summary per artifact in memory and writes them as `viewState` ops only when the learner sends their next message; replay renders them as `[view state <id>]` lines on that message in the provider request. The stored message stays what the learner typed. Summaries not followed by a message before the app quits are lost. | W7: ordinary interaction is not logged, and the learner's note must show their words only; one op per artifact per learner turn is enough to rebuild the request. |
| Plugin updates | No update command; installing another version of a plugin id is refused while any unfinished session is in Teach with that plugin active in its current section (checked before download and before the swap), naming the session. Not true per-session version pinning (several loaded versions per id): the registry holds one package per id, and tool dispatch, views and grading resolve by id. Startup loads the copy whose sha256 matches `plugins.lock`. A failed install/unpack leaves no directory behind. | W8 "never applies mid-session": a session keeps the version it was granted until its next section starts. Refusing is the narrowest correct form; pinning would need every id lookup in agent/view/grade paths to carry a package hash. The lock is the record of which version the learner chose. |

## Decisions in the model-catalog build (2026-11-07)

| Decision | Chosen | Why |
|---|---|---|
| Where model ids come from | Each provider's own listing endpoint, through `providers::models::list`. `ProviderSpec` carries no model ids; `suggested_models` is deleted. | A hardcoded table was wrong in both directions: it offered ids the account could not use (proxy, missing entitlement, retired) and missed every model released after the build. The provider is the only authority on what it serves. |
| Endpoints and shapes | Anthropic `/v1/models` (paginated by `last_id`, `limit=1000`, capabilities + `max_input_tokens`/`max_tokens`); Claude subscription the same URL with the OAuth beta headers; OpenAI `/v1/models`; Codex `/models?client_version=<app version>` (`models[]` presets with `slug`, `context_window`, `supported_reasoning_levels`, `visibility`, `supported_in_api`); OpenRouter `/api/v1/models` (`context_length`, `architecture.*_modalities`, `supported_parameters`); DeepSeek and Z.AI `/models`; WorkBuddy's `/v3/config` as before. One parser per shape, each unit-tested against a captured payload. | The shapes really differ; one lenient parser would silently read the wrong field. Anthropic and Codex report capabilities, so nothing is guessed for them. |
| Non-chat ids | OpenAI and Z.AI list embeddings, speech, image and moderation models next to chat models and state only ids, so a name denylist drops them; OpenRouter is filtered by its own `output_modalities` instead. | A picker that offers `text-embedding-3-small` invites a role that cannot work. Modality data is preferred wherever the provider states it. |
| Metadata a listing omits | The public models.dev catalog (`https://models.dev/api.json`, trimmed to the five provider keys on fetch) fills context window, output limit, vision, tool calling and effort levels. Live values always win; a field neither source states stays `None` = "unverified". | OpenAI's `/models` returns no limits at all, and role warnings plus compaction need real numbers. This is what pi does (its generated catalog is a models.dev snapshot). |
| Cache | `models-cache.json` in the config dir: one entry per provider with the base URL it came from, the fetch time and the models; the trimmed catalog with its ETag. 6 h TTL per provider, `refresh` bypasses it, a failed fetch falls back to the cached list (and only errors when nothing is cached). The catalog (a ~6 MB download) is waited for only when no copy exists; past its 7 d TTL the stale copy is used at once and a background refresh (one at a time, 304 revalidates without downloading) re-annotates the stored lists. A base URL change invalidates the entry rather than showing the other server's models. | Opening Settings must not fire one request per provider or wait seconds on metadata, a local OpenAI-compatible server must not inherit the hosted list, and losing the picker to a flaky network is worse than showing the last list. |
| Where the metadata is read | `Harness::model_info` (cache only, no network) behind `context_window` and `role_vision`; the picker goes through `Harness::models(provider, refresh)`. | Turns must never wait on a catalog request; a model the cache does not know is "unverified", which the vision gate already treats as "do not block". |
| Settings surface | The model field is a search combobox (`ui/modelsearch.js`) over the fetched list: with nothing typed it shows the first 10 in the provider's order, typing ranks matches on id and name (exact, prefix, word start, substring, all words, separators ignored) and shows the top 10 plus how many more match. All role pickers share one `list_models` call per provider. "Reload models" refetches with `refresh`, an empty list says so and leaves the id field usable, and `list_models` reports provider errors instead of an empty list. | The id is still free text (a private or brand-new model must be usable), so the list is a convenience and its absence must not look like "no models". The native datalist it replaced offered the whole list unranked. |

## Decisions in the durability, edge and PDF build (2026-11-07)

| Decision | Chosen | Why |
|---|---|---|
| A bad op line | Skipped, counted, warned once per read; `Session.skippedOps` carries the count. The rest of the file replays. | One unparseable line made a whole session unopenable while `list` still showed it, and a future op kind from a newer build would have done the same to an older one. Losing one op beats losing the session. |
| A torn tail | If the file does not end in a newline and the tail does not parse, truncate exactly at the last newline and reopen; if the tail *does* parse, append the missing newline instead. Nothing else is ever rewritten. | One `write_all` per op means a crash can only damage the tail; healing it there is repair, not data loss, and appending the newline stops the next op from gluing onto it. |
| Op durability | `append` syncs after every op. | The resumability story rests on the log; ops are tens per turn, not per streaming delta, so the fsync cost is bounded. `credentials.json` already synced. |
| Read-only rule | A session is a runtime session iff its **second line** is a `phase` op, and that single helper answers for `list`, `load`, `learn_ops` and every write path. | The two readers disagreed (line 2 vs "any phase op"), so a merged file could be listed read-only and written anyway. Line order is what an append-only file actually guarantees; a phase op anywhere else is treated as a hand edit and stays read-only on purpose. |
| Edge relations | `edges.jsonl` lines carry `relation` (`requires` | `contrasts`, default `requires` for older files). Only `requires` is a prerequisite: cycle checks, layout, arrows, `Depends on`/`Leads to` and the session porter use the requires view; a contrast is stored, reviewed and shown as "Contrasts with …" text. Duplicates and the cycle test are keyed per relation. | The extractor offered two relations and the store silently kept one, so an accepted contrast was taught as a prerequisite and could fail a cycle check it should never face. |
| PDF stack | `pdf-extract` + `lopdf` in `crates/harness/src/pdf.rs`; text-layer pages become page-tagged text, scanned pages become page images for a vision-capable Reader. No rasteriser, no OCR. | Both crates are in the offline cache, the parser sits next to the tools, and nothing C has to cross-compile to a phone. OCR would be a second, worse reader: the model sees the scan instead. |
| Where a page image reaches the model | The researcher's in-memory loop gets one extra user message (`ContentBlock::Image`) after the tool result, capped at four per run; nothing is written to the op log. | Researcher loops are already in memory, the block shape already exists for learner attachments, and a scan is read once, not replayed on every later turn. |

## Decisions in the graph, sync, plan-card and CI build (2026-11-07)

| Decision | Chosen | Why |
|---|---|---|
| Graph storage | `graph/ops.jsonl` is the source of truth (topic/node/place/edge/sameAs/chain/tombstone/split), folded in memory; the older `topics.json`/`nodes.jsonl`/`edges.jsonl` are migrated once and never written again. | Six writers each rewriting three files cannot be validated, merged or replayed. One append-only log validates in code, unions cleanly under sync (§4.18), and keeps every judgement (who placed what, why) on the record. |
| Where the builder runs | A `graph` job (Librarian role) at `session_end` and on `graph_build`; never delivers into the conversation and never wakes the tutor. | Arch §4.7's post-hoc timing; the graph is not conversation material, and a graph pass must not spend the tutor's attention or context. |
| Builder output | `graph_search` + `graph_submit`, validated by code (all problems at once, kinds incl. `heuristic` with attribution/scope, acyclic `requires`, per-relation duplicates, known ids). | Same shape as `plan_write`: the model proposes, code decides; a refused submit comes back as a fixable error instead of bad structure in the graph. |
| Field guide scope | Venues attach to **topics** in the graph (a `venue` op, read model `topicVenues` = own + descendants); the Map shows them per topic and on an idea's card, and the close keeps the session brief's venues. | A venue outlives the session that found it: a later builder run on the same topic refines one row instead of repeating it, so the guide grows across sessions and the Map can show it with no session at all. The close still owns "useful now" because its `entryLevel` is prose, not a level the code can compare. |
| Aliases and chains | `sameAs` folds later ids into the earlier node and remaps edges; a chain whose premises or conclusion have vanished is dropped with a log line. | Duplicate propositions are the normal failure of post-hoc extraction; folding them at the read model keeps the Map honest without rewriting history. |
| Topic splits | Connected components of a topic's internal `requires`, only above 30 nodes, ≥ 2 components of ≥ 5, written to `graph/splits.proposed.json` and applied by `decide_splits`. | Arch §4.5 asks for *suggestions* from real structure, not clusters that move on their own; a dismissal is remembered until the node set changes. |
| Sync transport | `git2` 0.21 with `vendored-libgit2`; HTTPS over the system OpenSSL on desktop and over OpenSSL built from source (`openssl-sys/vendored`) on Android. | §6.4's chosen option; vendoring libgit2 keeps the C dependency inside the build (libgit2-sys uses `cc`, so a cmake-less shell is fine). On desktop OpenSSL comes from the distro, which is what CI installs anyway; Android has no system OpenSSL to link. |
| Merge rules | `*.jsonl` union in code (drop unparseable lines, dedupe by `opId`, sort by `at`), anything else local-wins with the remote copy parked in `.conflicts/<path>.<timestamp>` and listed as needs-attention. | The op logs are the only files whose merge is decidable; guessing for JSON settings or prompt overrides would silently lose a learner's edit, so the loser is preserved and surfaced instead. |
| Sync triggers and failures | Best effort at launch and after `session_end`, single-flight, and `sync_now` on demand; a failure resets the index and records `lastError` for a banner. | R3: one device at a time, offline is normal. A merge is built in memory and written only once it succeeds, so a failed run cannot leave a half-merged tree. |
| Device-local sync config | `sync.json` (0600) holds the remote and token; a token embedded in a URL is stripped into it. | The token must never enter the repo, a commit message or a log line, and §4.18 keeps credentials out of the synced tree. |
| Plan card | Flowchart-first, a corner button expanding to the full-screen overlay, `⋯` inside each box opening a side drawer with the long description and the actions; per-box badges instead of a text list. | Owner verdict (2026-11-07): the flowchart and a wall of editable text side by side made the plan harder to read than to decide. The drawer keeps every control but hides it until the learner asks. |
| Reading measure | One shared rule, `--measure` stepping 56ch → 76ch (≥1024) → 92ch (≥1280) → 104ch (≥1600). | Owner: a fixed narrow column on a wide screen makes reading hard. The steps keep a measure below 1280 (where the old value was fine) and let the line grow with the window instead of capping it. |
| Bundles in CI | `appimage` on ubuntu-22.04 (`cargo tauri build --bundles appimage`) and **release** Android APKs, one per ABI (`cargo tauri android build --apk --split-per-abi`: arm64-v8a, armeabi-v7a, x86_64, each its own artifact and release asset), `zipalign -P 16` + `apksigner` with one release key from the repository secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, alias `release`); they gate nothing. | Owner wanted both artifacts from CI, and (2026-11-09) per-ABI APKs because the universal one was too big. The debug build was a signing workaround: its Rust library is ~460 MB (≈380 MB debug info) against ~26 MB stripped release, and Gradle's debug key is generated per runner, so each build would have needed an uninstall (losing local data) to update. One fixed key makes every build an update. |

## Decisions in the WebDAV, mobile-lock and sync-UI build (2026-11-09)

| Decision | Chosen | Why |
|---|---|---|
| Second sync target | WebDAV next to git, each optional and independent; one single-flight run does git then WebDAV, a failure is recorded on its own target and the other still runs. | Git needs a host, a token and OpenSSL; WebDAV is what free storage (Koofr, Nextcloud) speaks. Every merge is a union, so data relayed through either target converges. |
| WebDAV change detection | A three-way pass against `<config>/webdav-state.json` (remote ETag + local sha256, plus size/mtime with git's 2 s racy rule); conditional `PUT`/`DELETE` (`If-Match`/`If-None-Match`), a 412 re-merged up to three times, then the path is left for the next run. | WebDAV has no history; conditional writes are the only thing that stops two devices overwriting each other. Status reads stat-only, so the 60 s Home refresh never re-hashes the repo. |
| WebDAV client | `reqwest` (rustls) with a current-thread tokio runtime per pass; tests use an in-process server on `127.0.0.1`. | No OpenSSL on any platform; no new crate features; CI stays offline (no `rclone` dependency). |
| Mobile lock | A Learn session opens read-only on a phone only after a desktop-only plugin was **used** (tool call or artifact, platforms stamped on the op, else the cached index; unknown never locks); a `mobileUnlock` op (synced) releases the named plugins and drops their tools on phones. | Planning or granting is not use; guessing "desktop-only" would lock sessions wrongly; the op lets the learner decide once for every phone. |
| Sync UI placement | Settings → Sync (after Providers), a Home header status button + "Sync now", and a banner on Home only. | Owner decision: configuration where the other device-local settings live, status where the learner starts, nothing inside a session. |

## Known gaps in what is built

1. **No real-model run on record.** The runtime is proven against the scripted provider in `crates/harness/tests/runtime_e2e.rs` and `crates/harness/tests/learning_e2e.rs` (`cargo test -p harness --test runtime_e2e`, `--test learning_e2e`); how reliably real models quote `questionId`, shape `probe_done`, tag checks at the four levels, judge hunt eligibility, split a section on "parts I already know", honour explicit section settings, or sort a debrief is untested.
2. **The UI is verified in headless Chromium against a mocked backend,** not inside Tauri/WebKitGTK. The W6/W7 view checks (artifact placement, the view bridge and slider, the IPC-escape probe) are committed and re-runnable: `scripts/ui-check/run.sh`. The learning-system surfaces (plan "⋯" and `edit_plan`, known/refuted sections, the planner's question, the hunt card's return and skip, the close's guide and calibration, the Map's level/guide/confidence/frontier lines, Settings → Starting point) were driven the same way, with the same mock-bridge harness; those checks were throwaway, not committed.
3. **A turn already running is invisible when a session is opened after a restart;** the UI guesses from a trailing learner message and offers "Get a reply". Exposing "turn running" and "last turn failed" in `session_state` would remove the guess.
4. **Persisted native reasoning blocks** (`message.native`) have no size cap.
5. **Compaction** covers the tutor only and triggers on estimated size (characters / 4) against the catalog context window (100k when unknown).
6. **Interrupted jobs restart when their session is opened,** not at app start.
7. **WebKitGTK and mobile are unverified for the new surfaces.** The `srcdoc`/CSP finding, the IPC-escape probe, the view bridge and answer mode were verified in headless Chromium, with a separate HTTP origin standing in for the `pluginview` scheme and a mocked `window.__TAURI__`; the probe and placement checks are committed (`plugins/fixtures/ipc-probe`, `scripts/ui-check/run.sh`; 49 attempts, 0 escaped on Chromium 156). Still owed inside the real shell: that WebKitGTK (Linux) serves `pluginview://` frames with the response CSP and an opaque origin, that a sandboxed frame there gets no Tauri globals and cannot reach `ipc://` or `window.webkit.messageHandlers.ipc` (run the probe as a folder plugin; steps in `docs/plugins.md` §7.2), the native file picker and drag-and-drop paths, and the same on Android/iOS. **[inference]** Tauri's main-frame-only IPC injection should hold on every webview, but that is read from source, not observed.
8. **No real-model run of artifact placement.** The scripted provider proves the op log and the placement line; whether real models place `![alt](artifact:<id>)` next to the right sentence, or duplicate it, is untested.
9. **`luau-analyze` is not in the dev shell.** `plugin test` prints `luau-analyze: not installed (install the Luau CLI to type-check; tests still run)` and runs the Luau tests without the static type check. Put a `luau-analyze` binary on `PATH` to get checked types.
10. **Native dialogs and drag-and-drop are mocked in browser checks.** The file/folder picker and the Tauri drag-drop handler cannot run in headless Chromium; the UI's fallback paths (paste, browser drop) were exercised instead. WebKitGTK/mobile verification is gap 7.
11. **Only two model-catalog calls are proven live.** OpenRouter's `/models` (460 chat models, with context width, modalities and tools) and models.dev (trimmed to five providers, ETag revalidation) were run against the real services on 2026-11-07. The Anthropic, Claude-subscription, OpenAI, Codex and Z.AI/DeepSeek listings are unit-tested against captured response shapes only — no key or token was available — so a shape change there shows up as a "model list: …" protocol error, and Codex's `client_version` gate is unverified.
12. **Learning-system parts that wait for the graph or the coach.** The graph exists and its builder runs, and venues attach to topics (the `venue` op; the Map's guide and card section), but several graph-dependent parts of `docs/learning-system.md` §2/§5/§6 are not built: the `heuristic` node kind with `attribution`/`scope`, `hunt` provenance on nodes (and its `unverified` state until the debrief), and calibration per topic. The ops they will be built from are already recorded (`debrief` claims carry verdict/attribution/scope), so nothing is lost meanwhile. The coach's critique and design-to-constraints problems wait for the coach (arch §8 step 6). Separately, `plan_write` keeps `targetLevel` schema-optional so a plan written before levels stays revisable, which means a planner that omits it gets a section with no level gate; the plan sheet shows aim/known/refuted status and a free-text "Change plan", not the card's structured "⋯" controls (ui-design §7.7.1 ships it that way; `docs/learning-system.md` §4's "same controls on the plan sheet" is still owed); and the Map's confidence and frontier still come from the newest Learn session, not from a per-plan grouping the Map does not have (the guide itself is per topic).

13. **Sync is proven against local servers only.** Git: commit/fetch/merge/push, op-log union, `.conflicts/` parking and the readable failure paths run in unit tests against a temp bare repo; no real host and no token flow against GitHub/GitLab. WebDAV: the three-way pass, 412 re-merge, delete propagation and the git+WebDAV relay through a third device run against an in-process server on `127.0.0.1` (`crates/harness/src/sync/webdav_tests.rs`); never against Koofr, Nextcloud or any TLS server, and a server without ETags gets unconditional writes. No phone has ever synced. The mobile lock (`crates/harness/src/mobile.rs`, `tests/mobile_e2e.rs`) ran only through `Harness::set_platform("mobile")`, and the replayed `SessionState.platform` still always reads `desktop`, so on a phone the tutor's Platform line and the `plugin_request` refusal text say desktop. On Android, libgit2 and OpenSSL now compile from source (`openssl-sys/vendored`, `TARGET_RANLIB` pointed at the NDK's `llvm-ranlib` in CI); nothing has been pushed from a mobile build.
    *Android git trust (2026-11-09):* the vendored OpenSSL is built with `no-stdio` (`openssl-src` forces it on Android), so it can read no certificate file at all and every HTTPS remote failed. Two file-based fixes (`OPENSSL_CONFIG_DIR`, then `SSL_CERT_FILE`) found Android's roots and wrote them correctly but could never work, which only the owner's phone showed. Replaced: on Android libgit2's certificate callback verifies the leaf it received with rustls and the Mozilla roots, using the intermediates from a rustls handshake with the same host (`sync/tls.rs`, offline tests against a local rustls server). Proven end to end on desktop with OpenSSL stripped of roots (GitHub fetch accepted; a self-signed host and a wrong host name refused with rustls's reason); not yet run on a phone. User-installed CAs aren't trusted by git (`docs/unimplemented.md` §3).
14. **The graph builder and splitter have never run against a real model.** The `graph` job, `graph_search`/`graph_submit` validation, alias folding and split proposals are covered by scripted-provider tests (`crates/harness/tests/graph_e2e.rs`); whether a real Librarian model produces usable propositions, kinds and edges is unmeasured. The Map also has no surface yet for split proposals, learner drag-to-move, or a node's provenance; the read model carries them, the UI does not show them.
15. **No green Android bundle run is on record.** The `appimage` and `android` jobs were written from the Tauri CLI's `--help`, its embedded mobile template and its strings, and are debugged from real runs, as the owner asked. Fixes so far: `platforms;android-37.0` with an `android-37` alias, a library target for `crates/app` (`lib.rs` with `#[mobile_entry_point]`), `NDK_HOME` pointed at the r29 NDK, OpenSSL built from source for Android, `TARGET_RANLIB` set to the NDK's `llvm-ranlib` (the NDK ships no `aarch64-linux-android-ranlib`, which `openssl-src` otherwise runs), `pick_folder` compiled for desktop only (tauri-plugin-dialog has no folder picker on mobile; the mobile command returns an error the UI shows), and the plugin host's JSON bridge converting through `mlua::Integer`, which is `i32` on the 32-bit ABIs (armv7, i686); a JSON integer that doesn't fit becomes a Luau float there. The bundle identifier is `com.pslearningharness.app` (dash-free, so the Android package is legal). `release.yml` publishes the AppImage and APK a push run built. No APK has been installed on a device.
16. **Sync UI — built 2026-11-09** (`ui/sync.js`, `docs/ui-design.md` §7.1 and §7.5.2). Settings → Sync configures git and WebDAV separately (fields, state line, last error, Disconnect), runs Sync now and lists the needs-attention paths with Acknowledge. Verified in headless Chromium against the fake bridge (`scripts/ui-check/run.sh sync`), not inside Tauri/WebKitGTK or on a phone (gap 7).
## Agent roster (target)

Principles:
- **One live agent per conversation with the learner.**
- **The plan belongs to a separate planner**, so the tutor can't drift from it.
- **Any other separate agent** exists only when it must not know something, would flood the conversation, or doesn't work on the conversation.

Prompts and tool contracts are in `crates/harness/prompts/README.md`; the reasoning is in arch §4.10.

| Agent | Kind | Prompt | Tools (beyond shared core) | Model role (arch §4.22) |
|---|---|---|---|---|
| Tutor | live: measure + teach | `tutor/base.md` + `tutor/phases/{measure,teach}.md` + `tutor/modes/*` + the active plugins' `prompts/tutor.md` | measure: `goal_set`, `question_ask`, `verdict_record`, `probe_done`; teach: `question_ask`, `verdict_record`, `plan_change_request`, `plugin_request`, `section_done`, `session_end`, `workspace_write` (when a workspace is attached); always: `choice_ask`, `research_request`, `file_find`, `file_read` | Tutor |
| Planner | reads the whole session, speaks via the plan card | `planner/base.md` (+ `planner/exam.md`) | `plan_write`, `plan_keep`, `research` (blocking), `plugin_search` | Planner |
